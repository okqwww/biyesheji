# 毕业设计（论文）开题报告

**题目**：基于大模型与知识图谱的智能出题系统设计与实现

**学院**：电子工程学院  
**专业**：电子科学与技术  

---

## 一、选题的背景和意义

### 1.1 研究背景

随着高等教育规模的不断扩大和教学质量要求的日益提高，教师在教学工作中面临着越来越大的压力。其中，试题命制是教学环节中一项重要且耗时的工作。传统的人工出题方式存在诸多问题：首先，出题效率低下，教师需要花费大量时间和精力设计题目、编写选项、准备参考答案和评分标准；其次，题目质量参差不齐，容易出现知识点覆盖不全面、难度把控不准确等问题；再者，题目形式单一，难以满足多样化的考核需求。

近年来，人工智能技术的快速发展为教育领域带来了新的机遇。特别是以GPT、DeepSeek为代表的大语言模型（Large Language Model，LLM）展现出了强大的自然语言理解和生成能力，在文本创作、代码生成、问答交互等任务中表现优异。与此同时，知识图谱（Knowledge Graph）作为一种结构化的知识表示方法，能够有效地组织和管理课程知识体系，清晰地展示知识点之间的层次关系和关联关系。

将大语言模型与知识图谱技术相结合，应用于智能出题领域，具有广阔的应用前景。知识图谱可以为大模型提供结构化的知识约束，确保生成的题目紧扣教学大纲和考核要求；大模型则可以基于知识图谱的语义信息，生成形式多样、内容丰富的高质量题目。这种协同机制有望显著提升出题效率和质量，减轻教师负担，推动教育信息化发展。

### 1.2 研究意义

本课题的研究具有重要的理论意义和实际应用价值：

**理论意义方面**：本研究探索了大语言模型与知识图谱协同工作的技术路线，为人工智能在教育领域的应用提供了新的思路和方法。通过设计知识图谱驱动的Prompt工程策略，研究如何有效引导大模型生成符合教学要求的题目，丰富了大模型应用的理论体系。

**实际应用价值方面**：本系统面向高校教师，提供了一个便捷高效的智能出题工具。教师可以通过可视化的知识图谱界面直观地选择考察范围，系统自动生成多种类型、不同难度的题目，并附带参考答案和评分标准。这将大幅提升出题效率，使教师能够将更多精力投入到教学设计和学生指导中，对提升教学质量具有积极意义。

此外，本项目采用前后端分离的现代Web开发架构，涉及Vue 3、FastAPI、Neo4j、大模型API等多种技术，对于培养全栈开发能力和工程实践能力具有重要的锻炼价值。

## 二、研究的基本内容和拟解决的主要问题

### 2.1 研究的基本内容

本课题的研究内容主要包括以下三个方面：

**（1）课程知识图谱的设计与构建**

针对电子工程学院的编程类课程（Web全栈开发、Python编程基础），深入分析课程教学大纲和知识体系，设计合理的知识图谱Schema。知识图谱采用"课程-章节-知识点"的层次化结构，并建立知识点之间的关联关系。使用Neo4j图数据库存储知识图谱数据，每门课程包含30-50个细粒度知识点，支持知识点的可视化展示和交互式选择。

**（2）大模型驱动的智能出题模块设计与实现**

研究大语言模型在题目生成任务中的应用方法，设计针对不同题型（单选题、多选题、填空题、解答题）的Prompt模板。实现基于知识点的题目自动生成功能，支持难度等级控制（简单、中等、困难）。对于每道生成的题目，自动生成参考答案、解析说明，对于解答题还需生成详细的评分标准。采用DeepSeek API作为大模型服务，实现稳定可靠的题目生成能力。

**（3）Web系统原型的开发与集成**

基于前后端分离架构开发完整的Web应用系统。前端采用Vue 3框架和Element Plus组件库，实现课程选择、知识图谱可视化、出题参数配置、题目展示与编辑等功能页面。后端采用FastAPI框架，提供RESTful API接口，实现知识图谱查询、题目生成调度、题目存储管理等核心功能。完成前后端联调，确保系统功能完整、运行稳定。

### 2.2 拟解决的主要问题

**（1）知识图谱Schema的合理设计**

如何设计既能准确表达课程知识结构，又便于支撑出题功能的知识图谱Schema，是首先需要解决的问题。需要在知识点粒度、关系类型、属性定义等方面进行深入思考和权衡。

**（2）大模型输出的质量控制**

大语言模型的输出具有一定的随机性和不确定性，如何通过Prompt设计、参数调优、格式约束等手段，确保生成的题目质量稳定、格式规范、内容准确，是核心的技术挑战。

**（3）知识图谱与大模型的协同机制**

如何将知识图谱中的结构化知识有效地融入大模型的Prompt中，使生成的题目能够精准对应所选知识点，并体现知识点之间的关联性，需要设计合理的协同策略。

**（4）系统的用户体验优化**

如何设计直观易用的知识图谱可视化交互界面，如何在题目生成过程中提供良好的用户反馈，如何支持题目的便捷编辑和导出，都是需要关注的用户体验问题。

## 三、研究方法及措施

### 3.1 研究方法

**（1）文献研究法**

广泛查阅国内外关于知识图谱构建、大语言模型应用、自动出题系统等领域的学术论文和技术文档，了解领域研究现状和最新进展，为系统设计提供理论依据和技术参考。

**（2）原型开发法**

采用敏捷开发思想，快速构建系统原型，通过迭代方式逐步完善功能。先实现核心的题目生成功能，验证技术可行性，再逐步扩展其他功能模块。

**（3）实验验证法**

通过实际测试验证系统功能的正确性和生成题目的质量。设计测试用例覆盖各种题型和难度组合，评估大模型生成效果，根据测试结果优化Prompt设计和系统实现。

### 3.2 技术措施

**（1）知识图谱技术**

使用Neo4j图数据库存储课程知识图谱，采用Cypher查询语言进行图数据操作。前端使用ECharts或D3.js实现力导向图可视化，支持节点的交互式选择。

**（2）大模型应用技术**

选用DeepSeek API作为大模型服务，具有中文能力强、价格低廉、响应稳定等优点。针对不同题型设计专用Prompt模板，使用JSON格式约束输出结构，实现自动重试机制保证服务可靠性。

**（3）Web开发技术**

前端采用Vue 3 + Composition API + Element Plus技术栈，使用Vite构建工具，实现响应式的单页应用。后端采用FastAPI框架，基于Python异步编程实现高性能API服务。使用Axios进行前后端通信，采用RESTful API设计规范。

**（4）工程化措施**

使用Git进行版本控制，编写详细的技术文档和注释。采用模块化设计，确保代码结构清晰、易于维护。进行充分的功能测试和边界测试，保证系统质量。

## 四、研究工作的步骤与进度

本课题的研究工作分为以下八个阶段：

**第一阶段（2024.12.1 - 2024.12.14）：开题与技术调研**

明确课题研究目标和核心问题，完成开题报告撰写。深入学习知识图谱技术（Neo4j数据库、Cypher查询语言）、大模型应用方法（Prompt工程、API调用）以及Web开发技术（Vue 3、FastAPI），为后续开发奠定技术基础。

**第二阶段（2024.12.15 - 2024.12.28）：知识图谱设计与构建**

分析Web全栈开发和Python编程基础两门课程的知识体系，设计知识图谱Schema，确定节点类型、属性和关系类型。完成Neo4j数据库的本地部署，编写知识图谱数据文件，完成数据导入和验证。

**第三阶段（2024.12.29 - 2025.1.11）：大模型出题模块设计**

完成DeepSeek API的接入和调试，设计单选题、多选题、填空题、解答题四种题型的Prompt模板。实现基础的题目生成功能，测试不同参数配置下的生成效果，优化Prompt设计。

**第四阶段（2025.1.12 - 2025.1.25）：后端服务开发**

搭建FastAPI项目框架，实现Neo4j数据库连接模块。开发课程列表查询、知识图谱查询、题目生成、题目保存、题目更新等API接口。完成接口测试，确保各功能模块正确运行。

**第五阶段（2025.1.26 - 2025.2.8）：前端界面开发**

搭建Vue 3项目框架，设计并实现首页、课程选择页、知识图谱页、题目结果页等核心页面。集成ECharts实现知识图谱的力导向图可视化，开发题目编辑和Markdown导出功能。完成前后端联调。

**第六阶段（2025.2.9 - 2025.2.15）：系统集成与测试**

进行完整的系统功能测试，覆盖各种使用场景和边界条件。修复发现的Bug，优化系统性能和用户体验。完成系统部署文档编写。

**第七阶段（2025.2.16 - 2025.2.22）：论文撰写**

整理研究过程和成果，撰写毕业设计论文初稿。内容包括绪论、相关技术介绍、系统设计、系统实现、系统测试、总结与展望等章节。

**第八阶段（2025.2.23 - 2025.2.28）：论文修改与答辩准备**

根据导师反馈意见修改论文，完善格式和内容。制作答辩PPT，准备答辩演示，进行预答辩演练，做好最终答辩准备。
